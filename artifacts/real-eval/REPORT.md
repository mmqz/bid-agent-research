## 3. 评测驱动的修复与发现（三轮）

### 已修复（真实 bug / 真实缺口，corpus-A 回归保持全绿）
1. **阿拉伯数字章节失配**：真实水利文件用"第2章 投标人须知"（合成夹具/政采范本用"第三章"）→ 章节正则双通道化（数字+中文数字+空格容忍）。
2. **多页扫描件页数错报**：8 页扫描补遗被报"1 页"（pdftotext 空文本层口径）→ OCR 渲染张数回写。合成夹具 B2 是单页扫描件，曾掩盖此缺陷。
3. **目录行建立章节上下文**：目录条目（带页码引导点）不再更新章节。
4. **无编号条款盲区**（首轮漏项主因）：否决/资格/评分细则大量存在于前附表与无编号行——按风险不对称原则（漏否决条款=废标风险 > 误报可过滤）增加三条通道：强否决短语行（将被否决/视为无效/取消中标/没收）、资格面行（资质等级/资格审查/营业执照…）、评分算法行（评标基准价/下浮率 K——基准价算法常在须知章而非评标办法章）+ 续行窗跨行还原。
5. **编号行自带资格词**（"1.4.1 投标人资质条件、能力和信誉"）→ 资格条件优先于章节上下文。

### 已知差距（诚实登记，不在本轮打补丁——根因属既有设计边界）
- **表格两列拆行**（GT-R05"能力和信 誉"被拆列）：D1 表格结构抽取面——corpus-R D1a 已实证引擎差距，业务侧 M2+。
- **长条款跨行拆断**（GT-S03/S04/S05 评分算法行被 layout 拆碎）：行级抽取的天花板，解法同上。
- **技术参数 0/2**：确定性型号正则对水利工程文件（无 IT 型号谱系）天然失效——"什么算技术条款"是语义问题，归 M2 模型辅助归类（设计内）。
- **OCR 错字噪声**（02 号"满分 20 分郑"多字、"闽水规〔2024〕"→"国水规[52024]"）：tesseract chi_sim 公文体基线；对齐层 norm_n2 容忍有效，但真实 OCR 质量需 D5 管道面持续评测。
- **GT-T02 标注争议**："投标人已进行信息登记，资质符合…"更像形式审查而非技术参数——GT 人工验收时改判。
