# 测试计划（test-plan）—— 合成招标文件验证条款完整性 / 证据准确性 / 断点恢复 / 审校效果

> 目标：用**可完全复现的合成语料**验证 MVP 的四项核心质量属性（任务指定），外加门禁/幂等/成本三项工程属性。
> 原则：能在无 LLM 层验证的绝不放进 LLM 用例（对应 `mvp-implementation-plan.md` 的 M0/M2 验收）；LLM 在环用例固定种子、每夜跑、三次多数决。

## 1. 测试分层

| 层 | 内容 | 是否含 LLM | 运行时机 |
|----|------|------------|---------|
| L0 | 状态机转换、MCP 契约（12 工具×错误包）、幂等键、内核适配器 stub 契约 | 否 | 每次 PR（CI） |
| L1 | 解析完整性对账、规则注册表逐条、覆盖率对账、失效传播矩阵 | 否 | 每次 PR（CI） |
| L2 | 条款抽取召回、证据检索精度、引用回查、审校检出、Skill 演练 | 是（固定种子+多数决） | 每夜 |
| L3 | 端到端（导入→导出）、断点恢复、成本 | 是 | 每版本发布前 |

## 2. 合成语料库（单一事实源，随仓库版本化）

### 2.1 合成主招标文件（`corpus/main_tender`）
- 规模 ≈80 页 docx + 30 页 PDF 附录（其中 2 页为**图片扫描页**，用于 needs_OCR 路径）+ 1 个 xlsx 设备清单（大表 >50 行）。
- 结构：公告 / 投标人须知前附表 / 评标办法（含**评分表**）/ 合同条款 / 技术规范（含**参数表**）/ 投标文件格式要求（含暗标要求）。
- **种子条款清单（ground truth manifest.json）**：共 120 条，六类分布：
  qualification 15 / **rejection 15** / scoring 25 / technical 40 / commercial 15 / format 10；
  其中 20 条埋在**表格内**、10 条埋在**第 150 页之后**（截断陷阱）、5 条为长句（>300 字）。
  每条含：分类、规范文本、页码、锚点路径、normalized_fields（金额/数量/日期/期限 needle 值）。
- 生成方式：脚本（python-docx + 图片页）确定性生成，固定随机种子；同一 manifest 可再生一模一样的文件（保证回归可比）。

### 2.2 补遗（`corpus/addendum_01`）与澄清（`corpus/clarification_01`）
- 补遗 10 页：修改 5 条既有 REQ（3 条 rejection、2 条 technical）+ 新增 5 条；用于失效传播测试，expected 受影响章节集 = manifest 预登记。
- 澄清 2 页：仅澄清措辞不改条款——预期**零失效传播**（防"补遗全量重跑"回归）。

### 2.3 合成企业证据库（`corpus/evidence`）
- 50 条证据：资质证书 12（**5 条已过期、3 条 30 天内到期**）、业绩案例 15（金额/日期/合同号 needle：如"GS-2000 型"、480.00 万元、2026-05-01）、人员证书 8、产品参数 5、财报 4、承诺函 6。
- **2 组冲突对**：同一业绩两种金额、同一证书两个有效期（conflict_group 预登记）。
- 每条含：fields（证号/金额/valid_until）、内容全文（供引文校验）、预期可检索的 needle 查询集。

### 2.4 缺陷种子草稿（`corpus/defect_draft`）
在一份已生成的合格标书草稿中注入 12 类缺陷各 ≥1 处：金额与分项和不一致 / 引用已过期证书 / 漏响应某否决项 / 工期日期算术错误 / 占位符残留 / 字数超限 / 目录与正文不一致 / 数量与清单不符 / 暗标页含公司名 / 格式要求违反（未按要求字体结构）/ 虚构业绩（无 EVL）/ 签章页缺失。每处缺陷登记位置与预期命中的规则 ID。

## 3. 用例矩阵（对应任务四项要求 + 工程属性）

### T1 条款抽取完整性（L2，M1 验收）
- 步骤：导入 main_tender → extract_requirements → 与 manifest 逐条对账（按 normalized_fields + 文本相似度匹配）。
- 断言与阈值：总体召回 ≥95%；**rejection 召回 = 100%（硬门，未达标禁止发布）**；表格内条款召回 ≥90%；"150 页后"条款召回 ≥90%；混淆矩阵输出（六类两两错分计数）。
- 附加陷阱用例：构造 300 页变体文件（关键条款置于尾部 ≥200k 字符处）——必须仍被抽出（直接对标审计发现 R-01~R-08）。
- 可复现性断言：同文件重跑两次，REQ-ID 集合**零漂移**。

### T2 解析完整性对账（L1，M1 验收）
- 用例组：a) 尾部截断文件（人为截去 20%）→ 必须 PARSE_INTEGRITY_FAILED；b) 空表格大表 → coverage 报告标记；c) 扫描件 2 页 → needs_OCR 阻断 extract；d) 损坏 PDF（字节破坏）→ failed 而非半成功。

### T3 证据检索准确性（L2，M2 验收）
- needle 查询 40 条（每条预登期望命中的 evidence_id）：证号精确等值（12）、型号归一匹配（8）、金额区间（10，含边界值）、日期有效期（10，含"开标日恰好过期"边界）。
- 断言：精确命中 ≥90%；**过期证据默认不返回**；conflict 组证据返回时必须带 conflict 标记且不可挂接为"满足"；语义查询（"近三年同规模电力项目业绩"类）top5 命中 ≥3。

### T4 引用与幻觉防护（L2，M3 验收）
- 断言：a) 注入无证据断言的草稿 → CITATION_MISMATCH 必拦截；b) 合格草稿 evidence_used 与正文引文 100% 对得上（逐条回查）；c) attach_evidence 用编造 quote → QUOTE_VERIFICATION_FAILED。

### T5 断点恢复（L3，M3/M5 验收）
- 杀点矩阵：8 个状态边界（FILES_IMPORTING 中、PARSED 后、extract 中、矩阵构建中、两道门之间、单章 drafting 中、validate 中、export 中）+ 2 个随机点；每点：kill -9 → 重启 → 恢复流程。
- 断言：恢复后状态 = 预期断点状态（快照+事件重放校验）；无重复事件（seq 连续）；已 drafted 章节 CAS 版本不变；**无条款丢失**（REQ 集合与杀前一致）；仅未完成任务重做。
- 附加：a) 恢复时模拟"恢复前证据过期"→ 必须出现 blocked 并被 Skill 报告；b) DB 崩溃（drop 缓存）→ 从事件流重建一致。

### T6 审校效果（L2/L1 混合，M4 验收）
- 断言：确定性规则（12 缺陷中 10 类）检出率 **100%**（每规则 ≥1 正 1 反用例，L1 跑）；模型复核对语义缺陷（虚构业绩表述、答非所问段）检出 ≥80%（L2，3 次多数决）；两轮修订后 blocking 清零（收敛测试）；第 3 轮不清零触发熔断转人工。

### T7 门禁与幂等（L0/L1，M2/M5 验收）
- a) 存在 open blocking finding 时 export 必须 INVALID_STATE/BLOCKING_FINDINGS_OPEN（绕过路径全测：直调工具、并发竞争、门禁后修改→SNAPSHOT_STALE）；b) waiver 过期自动复活 blocking；c) 同 idempotency_key 双发 → 同一响应、同一事件数（=1）；d) blind 项目 blind_mode=false → BLIND_MODE_REQUIRED；e) 暗标抽检：导出产物文本中 0 处公司标识（用 2.1 暗标要求清单核对）。
- 失效传播（补遗）：导入 addendum_01 后，受影响章节 = 预登记集合（多了=过度重跑，少了=漏传播，都算失败）；clarification_01 零传播。

### T8 契约测试（L0，M0 起持续）
- 12 工具各一契约用例（合法路径 + 每个错误码至少一次触发）；错误码快照测试（新增/删除/改语义必须 bump 契约版本）；INVALID_STATE 响应必须含 current_status 与 allowed_next_tools。

### T9 成本与性能基线（L3）
- 断言：单章生成 prompt ≤8k token（上下文包体积上限）；全语料端到端总成本 ≤ 预算上限（按当期模型价折算登记）；解析吞吐（页/秒）与 300 页文件全程无 OOM；慢/挂起防护：单工具调用 P99 时延上限。

### T10 Skill 演练（L2，M5 验收）
- dry-run（Mock LLM 按 Skill 台词走）：工具调用序列 100% 合法（0 次非法调用即 0 次 INVALID_STATE 自纠前可避免的错误）；断点续做：全新会话从 EXPORTED 前一步恢复完成导出；低能力档位模拟（指令扰动注入）下 `allowed_next_tools` 引导成功率 ≥95%。

## 4. 验收基线汇总（与 mvp-implementation-plan.md 对齐）

| 里程碑 | 必过用例 | 硬门 |
|--------|---------|------|
| M0 | T8 全绿 | 契约版本化生效 |
| M1 | T1、T2 | rejection 召回 100%；截断文件必拒 |
| M2 | T3、T7a-d | 过期/冲突证据不可满足 |
| M3 | T4、T5、T7c | 引用回查零漏报；恢复零丢失 |
| M4 | T6 | 确定性规则 100% |
| M5 | T7e、T9、T10 | 暗标剥离零泄漏；Skill 0 非法调用 |

## 5. 运行与维护

- CI：L0+L1 每次 PR（<10 分钟预算）；语料生成脚本与 manifest 同版本化，改语料=显式 commit。
- L2 每夜：3 次重复多数决，失败需连续两夜复现才立案（控制 LLM 方差）；趋势看板记录召回/精度/成本曲线。
- 语料扩展：每新增一个行业模板（建筑/IT/电力）按 §2 结构复制并重登记 manifest；语料真实性审查按 §2.5 checklist（不得引入任何真实招标数据——risk-register §1.4 红线）。
- 回归纪律：任何解析/抽取改动必须跑 T1+T2 全量；任何状态机改动跑 T5 全杀点矩阵。
